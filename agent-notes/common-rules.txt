Hard rules:
- **Graphics quality:** never reduce graphics or effects quality. Performance work must be pixel-identical.
- **Sim determinism:** the sim is deterministic lockstep: 20 TPS, seeded RNG, NEVER `Math.random` in sim code, no render state in the sim.
- **Content:**
  - no real brands in ads;
  - Iran has no fighter jets;
  - no concrete pad markings under buildings.
- **Browsers:**
  - Chromium: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` with args `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`, via `playwright-core`.
  - Wrap EVERY browser run in `flock /tmp/claude-0/pw.lock node ...`, so only one browser runs at a time on this machine. Other agents share this lock, so keep each run short and don't hold the lock idle.
  - Serve your own build with `npx vite build && npx vite preview --port <your port> --strictPort` from your worktree's `web/`. Symlink `node_modules` from `/home/user/ra2/web/node_modules` if it is missing.
  - Software GL is slow: 1.5–3 min per page load.
- **Processes:** never `pkill -f` / `pgrep -f` with patterns that could match your own shell.
- **Debugging helpers:**
  - URL: `?play=usa,russia,normal&brief=0&map=frontline&warm=0` (phone: viewport 860x400, dpr 2.6, `q=medium&controls=simple`, isMobile/hasTouch).
  - Debug handle: `window.ironfront.game`.
  - Existing helper scripts live in `/tmp/claude-0/pw/`.

    - meshes must fit the phone triangle budget;
    - check the phone frame time stays the same.
  - Blender runs CPU-heavy: render small, keep sample counts modest, and do not run more than one Blender process at a time per agent.
